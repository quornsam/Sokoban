BOXXY v124 — RELEASE TEST REPORT
================================

RELEASE BASIS
-------------
Rebuilt from the user-supplied BOXXY v120 source rather than patching the
faulty v123 archive. The finished package is named BOXXY_v124 and contains no
nested v120 folder.

PASS — JAVASCRIPT SYNTAX
------------------------
Node syntax checks completed successfully for:

  boxxy.js
  data.js
  solver-worker.js
  solver-route-verifier.js

PASS — INDEPENDENT ROUTE VERIFICATION
-------------------------------------
solver-adapter-tests.js replayed all 50 stored Microban solution strings from
their original player positions. Every movement and push was legal and every
final box occupied a goal.

Additional verifier cases passed:

  already-solved board with an empty route
  illegal movement into a wall
  illegal route character
  harmless whitespace around a route
  XSB padding outside an irregular map treated as blocked void
  legal movement sequence that does not solve the puzzle

The external solver's success flag is therefore not trusted by itself. BOXXY
replays the returned route and rejects it unless the route is legal and solves
the supplied board.

PASS — WORKER/ENGINE ADAPTER CONTRACT
-------------------------------------
The exact v124 worker source was tested against a temporary mock module using
the same exported API shape as the Rust/WebAssembly engine.

Verified message sequence:

  loading -> ready -> progress -> result

Verified mappings:

  explored
  frontier
  iterations
  progress timeElapsed in seconds
  solved
  solution
  moves
  pushes
  nodes_searched
  time_ms in milliseconds
  fail_reason
  solver job ID

This specifically checks the elapsed-time unit error present in the earlier
attempt.

PASS — OLD SOLVER REMOVAL
-------------------------
The active release contains no:

  solver-core.js
  FESS search interface or status wording
  closest-position panel
  old solver regression harness
  main-thread JavaScript solver fallback
  interrupted-search snapshot promises

index.html loads only:

  data.js?v=124
  solver-route-verifier.js?v=124
  boxxy.js?v=124

The solver worker is created as an ES module and has only the Rust/WASM engine
adapter. Cancel Search terminates that worker immediately.

PASS — HTML AND PACKAGE INTEGRITY
---------------------------------
Checked that all required solver controls exist and all local HTML references
resolve to files in the release folder. Application script and stylesheet
cache tags are v124. No stale application or package references to v110-v123
remain in active files.

PASS — GAME DATA AND ASSETS PRESERVED
-------------------------------------
The full assets directory is byte-for-byte identical to the uploaded v120
source. The level-pack content in data.js is unchanged after its version-header
line. Existing artwork, music, sounds, skins and level data are therefore
preserved.

PASS — WORDING FIX
------------------
The completion title now uses:

  GUIDED SOLVE

instead of WALKTHROUGH USED, preventing the longer word from being cropped.

RUNTIME ENGINE AND INTERNET REQUIREMENT
---------------------------------------
The upstream repository did not display an explicit redistribution licence
when this release was prepared. BOXXY therefore does not bundle a copy of the
third-party Rust source, JavaScript binding or WebAssembly binary.

At solve time, solver-worker.js first loads the browser module pinned to
upstream commit:

  d355ece7272ec89071056ef64ce257c797f9c2b1

Primary module URL:

  https://cdn.jsdelivr.net/gh/dangarfield/sokoban-solver@d355ece7272ec89071056ef64ce257c797f9c2b1/festival-rust/pkg/festival_rust.js

Fallback module URL:

  https://dangarfield.github.io/sokoban-solver/festival-rust/pkg/festival_rust.js

The associated WASM binary is resolved by the upstream JavaScript binding.
Normal BOXXY gameplay remains local. The solver requires an internet
connection and must be run from GitHub Pages or another web server rather than
opening index.html directly from disk.

NOT RUN IN THIS BUILD ENVIRONMENT
---------------------------------
A complete live solve through the remote upstream WASM module was not run in
the packaging container. Its browser process is blocked by an administrator
navigation policy, and the container itself has no general outbound DNS.

Accordingly, this report does not claim a live Chessboard 12 result. The local
integration, message contract, timing conversion, route replay, removal of the
old engine, data preservation and package structure were tested as described
above. The first practical check after uploading should be a small Microban
level, followed by the desired benchmark packs.
