BOXXY v126 SOLVER ADAPTER TEST REPORT
========================================

Release structure
- Top-level release directory: BOXXY_v126
- No solver-core.js
- No legacy FESS worker
- No JavaScript main-thread solving fallback
- Active cache identifiers: v126

Engine-loader checks
- Remote JavaScript is fetched as text, avoiding strict cross-origin module
  MIME/import handling.
- The JavaScript is imported from a same-context Blob module URL.
- Matching WASM bytes are fetched separately and validated for the WebAssembly
  magic header before initialisation.
- WASM bytes are passed explicitly to the generated initialiser.
- Three source pairs are attempted: pinned GitHub raw, pinned jsDelivr, and
  the maintainer's GitHub Pages deployment.
- Failed engine initialisation clears the cached promise, allowing Retry.
- Detailed per-source errors are displayed rather than only "unavailable".

Solution safety
- Returned route strings are independently replayed against the exact XSB map.
- Illegal movement, illegal pushes and unsolved final positions are rejected.
- Empty routes are accepted only when the starting board is already solved.

Static checks performed during packaging
- JavaScript syntax check: passed for boxxy.js, solver-worker.js and
  solver-route-verifier.js.
- HTML references check: passed.
- Legacy FESS/search-source filename check: passed.
- ZIP extraction and top-level folder check: passed.

Limitation
- The packaging environment could not perform an outbound browser execution of
  the third-party WASM engine. The loader has therefore been tested statically,
  not by claiming a benchmark solution that was not observed.
